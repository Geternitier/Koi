01 / 现状诊断

她不缺功能，
缺一个像她的入口。

当前页面只有 283 行 HTML、一个 SSE 接口和 260px 侧栏。它足够把话说通， 却装不下一个人格体的在场感、异步性和情绪。下面 8 个问题按优先级排列， 前三个会直接影响“能不能用”，后五个决定“愿不愿意每天打开”。

P0 · 在场01

首屏没有“她”

一块空白画布、一个灰色输入框、右侧一列字段。没有头像、没有问候、没有“她现在在做什么”。人格体的第一印象被降级成一张状态表。

影响：像工具，不像她改法：顶栏在场 + 空态问候 + 状态语
P0 · 可达02

手机上，待办直接消失

@media (max-width:720px) 把整个 aside 设为 display:none。审批、扫码、验证码和操作记录在手机上全部不可达；输入框还会因为固定高度溢出视口。

影响：手机端无法处理审批改法：底部导航 + 待办浮层 + 安全区
P1 · 可读03

状态是数据库字段，不是感受

心情写作“效价 0.38，唤醒 -0.16”，精力只有一根没有刻度的橙色条。用户既不知道 84 是高还是低，也不知道她会不会在十分钟后睡着。

影响：数字看不懂，状态无意义改法：能量环 + 心情坐标 + 阈值提示
P1 · 反馈04

发送之后，没有“正在发生”

POST /api/messages 返回 202 后界面什么都不做；她思考、调用工具、等待审批都没有可见过程。SSE 断开时页面只会一直安静，用户分不清是她在想还是进程挂了。

影响：不确定、重复发送改法：发送三态 + 活动流 + 连接横幅
P1 · 层次05

对话没有时间与层次

系统消息、她的回复、你的消息、内心独白都共用一种气泡；没有日期分隔，没有工具动作，也没有“这段话是插件说的”。长对话很快变成一条无法回看的流水。

影响：上下文丢失，无法回看改法：消息类型系统 + 日期 + 工具行内记录
P2 · 纵深06

记录与记忆被藏起来

操作记录折叠在 <details> 里，要展开才请求；插件状态与记忆只存在于 /api/state 和 README，LLM 统计则挤在侧栏底部。她越活越久，界面越显得空。

影响：她的生活不可见改法：记录视图 + 记忆视图 + 运行页脚
P2 · 边界07

输入框的边界没有处理

textarea 固定 44px；390px 宽度下按钮与提示文字溢出；没有字数上限提示、没有发送中禁用、没有 Esc 收起。中文输入法下的 Enter 也没有明确约定。

影响：移动端输入体验破损改法：自适应高度 + 计数 + 发送状态机
P2 · 气质08

视觉与人格脱节

系统默认字体、纯色块、无品牌记号。任何聊天应用都可以长成这样，但它偏偏是 Koi：一个有作息、有心情、会拒绝你的存在。

影响：没有记忆点，也不像“家”改法：池畔视觉语言 + 可调节安静度

02 / 设计原则

先让她在场，
再让功能就位。

六个原则里，没有一条是“加更多”。它们大多在约束界面：少一点仪表盘、 少一点打断、少一点假装在线。Koi 的特别之处不是能力列表，而是她可以不在。

01

她先于功能

每一屏先回答“她在哪、在做什么、心情如何”，再回答“你能做什么”。身份、状态和一句人话，必须出现在第一眼。

Presence first
02

聊天是客厅

80% 的时间只做一件事：说话。状态、记忆、记录是侧房，从导航进入，不抢主位；聊天永远是最短路径。

Conversation first
03

状态要能读出来

每个数字都要有刻度、翻译和后果：“精力 84，还能撑大约 6 小时”“困意越过 0.66 就会去睡”。不做无法解释的仪表盘。

Legible inner state
04

打断要有分寸

审批与登录是请求，不是通知。只在她真的卡住时出现，必须给出来源、范围、后果和退路；一次只问一件事。

Respect attention
05

每个动作有回声

发送、思考、调用工具、等待批准、失败重试，都有可见的中间态。宁可显示“她还在想”，也不要让界面假装什么都没发生。

Visible state
06

允许她不在

睡着、发呆、离线都是产品状态，不是错误。消息可以留在枕边；不必用“正在输入”伪造永远在线。

Async by design

“你可以晚一点回我。但别把‘她睡着了’做成一个报错。”

—— 本次改版对“异步人格体”的一条硬约束

这次明确不做

  • 不做全天候在线的假象
  • 不做签到、等级、连续对话天数
  • 不做堆满数字的“人格仪表盘”
  • 不用动画掩盖真实延迟
  • 不把审批做成弹窗雨
  • 不让吉祥物替错误卖萌
03 / 视觉语言

纸、水、墨，
和一点朱砂。

视觉方向叫「池畔 Pondside」：以宣纸为底、池水为主色、墨色写正文， 朱砂只留给“需要你”的瞬间。它不靠粉色和圆角卖萌，而靠留白、细线和一点点水的动势， 让界面安静下来。

04 / 信息架构与布局

聊天是客厅，
其余是侧房。

桌面端用一条窄导航把“聊天 / 此刻 / 记忆 / 记录”分开，右侧保留一块常驻的“她的此刻”。 平板把右栏收成抽屉，手机把导航移到底部，并把待办钉在输入框上方。

她 对话，是唯一的主路径
聊天消息、独白、工具动作、待办摘要PRIMARY
此刻精力、心情、困意、日程、下一次醒来PHASE 1
记忆日记、笔记、她愿意给你看的片段PHASE 2
记录工具审计、插件状态、LLM 用量PHASE 1
设置昼 / 夜、动效、连接信息、实例切换PHASE 2

桌面 ≥ 1020 68 + fluid + 334

左窄栏只放导航；中间聊天最大 760px；右侧常驻“她的此刻”。窗口再宽也不把正文拉长。

平板 760–1020 抽屉

右侧栏变成可滑出的抽屉，聊天仍占主位；顶栏保留“她”的入口和一个待办徽标，不默认遮挡对话。

手机 < 760 390 基准

导航移到底部；待办钉在输入框上方；右栏改成全屏上滑面板。输入框跟随安全区，键盘弹起时不遮住最后一条消息。

  • 间距：4 的倍数；聊天区块 16 / 24，卡片内 12 / 16，页面边距 18 / 30。
  • 断点：1020（右栏收成抽屉）、760（导航移到底部 + 全屏面板）、420（隐藏品牌名）。
  • 最大宽度：聊天气泡 570，聊天列 760，页面内容 980；永远不要把中文正文拉过 38 个字。
  • 安全区：手机底部用 env(safe-area-inset-bottom)；输入框在键盘上方保留 8px。
  • 滚动：只有消息列表、右栏、页面内容滚动；顶栏、输入框、底栏固定，不整页滚动。
  • 焦点：任何浮层打开后焦点进入面板，Esc 关闭并回到触发按钮。

“睡着了 / 等你批准 / 等你扫码 / 闹情绪 / 空对话”会同时改变对话、右栏、顶栏和输入区，而不是只换一张图。

ANNOTATIONS 六个关键设计决策

01在场首屏名字、状态、时间与一句人话，先于任何操作出现。
02待办有位置审批与登录固定在右栏顶部；手机上钉在输入框上方。
03独白可折叠内心独白是她的一部分，但默认轻量，不抢对话。
04发送三态可发 / 发送中 / 她睡着；按钮与提示同步，不假装已读。
05侧房导航聊天、此刻、记忆、记录各就各位，主路径仍然只有一条。
06连接与昼夜连接是状态，不是错误；夜灯跟随她的作息，也可手动切换。
06 / 关键流程

把“等她”，
变成看得见的过程。

聊天界面的难点不在气泡，而在气泡之间的空白：她睡着时、思考时、卡在审批时、 连接断掉时。下面四条流程决定了这套界面是否真的“像一个活着的她”。

她睡着时找她

WAKE · 不假装在线

睡眠不是错误页。输入框仍然可用，但先告诉她“发出去会发生什么”：消息会留在枕边，或者现在就叫醒她。

01 看到“睡着了”→ 02 输入提醒→ 03 发送 / 叫醒→ 04 起床气回复→ 05 回到发呆
文案：“她睡着了。消息会放在枕边，也可以现在叫醒她。” 状态：叫醒后顶栏立即变“正在想”，不伪造“已读”。 边界：不自动替用户叫醒；不把起床气写成错误提示。

一次审批

APPROVAL · 只问一次

工具调用越过工作区时，她先停下来。审批卡必须回答三个问题：她想做什么、范围到哪里、批准后会发生什么。

01 工具请求→ 02 右栏卡片 + 徽标→ 03 允许 / 拒绝→ 04 系统回执→ 05 她重试并记录
信息：动作、路径、读 / 写 / 删除、一次性 / 目录级、来源插件。 动作：主按钮“允许这一次”；“拒绝”永远同级可达；不提供“全部允许”。 回执：“你批准了「读取文件」，她会自己继续。”不要求用户再去催她。

扫码与验证码

INTERACTION · 敏感值不经过她

插件要登录时，二维码、链接、验证码输入都在同一个卡片里。提交成功后，她只收到“登录好了”，看不到具体值。

01 插件请求→ 02 二维码 + 倒计时→ 03 扫码 / 填码→ 04 插件完成→ 05 她只收到结果
输入：敏感字段用密码框；提交后清空，不回显。 兜底：“也可以把 6 位验证码直接发在聊天框”，由后端截获，不进入她的记忆。 过期：倒计时结束变“已过期，请让她重新发起”，不留下死卡片。

断线与恢复

RECONNECT · 她可能还在

SSE 断开不等于进程死亡。界面先显示“没连上她，正在重试”，保留已有对话；恢复后补齐历史，不重复消息。

01 SSE 断开→ 02 顶部横幅→ 03 1/2/4/8s 退避→ 04 历史对齐→ 05 “已重新连上”
不假装：断开期间禁止发送，或明确进入“离线草稿”，不显示“已发送”。 去重：消息需要稳定 ID；重连时以 ID 合并，而不是重放整段历史。 手动：横幅提供“立即重试”和“检查进程”，不逼用户刷新页面。

08 / 落地计划

不引入构建链，
也能做得好看。

当前 Web 插件刻意保持“无前端构建”。这次继续沿用：把单文件拆成 HTML + 一份 CSS + 一个原生 ES module，由 FastAPI 静态托管。 没有 npm、没有 CDN、没有运行时框架。

验收标准

  • 390 / 768 / 1280 三档宽度无横向滚动，输入框不溢出。
  • 手机上可以完成审批、扫码与验证码提交。
  • SSE 断开后 8 秒内出现横幅，恢复后消息不重复。
  • 所有交互元素可键盘到达，焦点可见，Esc 可退出浮层。
  • 正文对比度 ≥ 4.5:1，状态不只靠颜色区分。
  • 尊重 prefers-reduced-motion，关闭涟漪与呼吸动画。
  • 首次渲染不请求字体 CDN，不依赖任何外部资源。
  • 现有 pytest 全绿；新增路由有最小覆盖。
最大风险不是样式，是范围。“记忆”和“多实例”都很诱人，但它们需要协议与核心改动。建议 Phase 1 只交付“聊天 + 待办 + 连接”三件事，先让每天打开它的人感到顺手，再谈更深的侧房。
